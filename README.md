# Сокращатель ссылок

Консольный сервис коротких ссылок с лимитом переходов и временем жизни. Java 17, Maven.

```bash
mvn package
java -jar target/short-link-1.0.0.jar
```

Свои настройки можно передать файлом: `java -jar target/short-link-1.0.0.jar my.properties`.

## Как пользоваться

1. Запускаем приложение и сокращаем ссылку, лимит переходов можно не указывать:

   ```text
   guest> create https://www.baeldung.com/java-9-http-client 5
   Создан пользователь 4b664cab-0f8e-4419-b051-1223c8857e28
   Короткая ссылка: mifi.test/fPgqZ2
   ```

   При первом `create` создаётся UUID, он сохраняется в `data/user.txt`, после перезапуска вы остаётесь тем же пользователем.

2. Переходим: вставляем короткую ссылку в консоль (или `open mifi.test/fPgqZ2`), она откроется в браузере. Домен `mifi.test` учебный, в самом браузере такая ссылка работать не будет, только через приложение.
3. Смотрим свои ссылки: `links` покажет переходы, срок и статус.
4. Управляем: `limit`, `edit` и `delete` работают только для своих ссылок.
5. Когда лимит кончится или пройдут сутки, ссылка перестанет открываться, а в консоли появится уведомление. Протухшие ссылки удаляются сами.
6. `user` покажет ваш UUID, `user <uuid>` вернёт к ссылкам этого пользователя, `logout` забудет UUID.

## Команды

Полный список выводит `help`.

```text
create <адрес> [лимит]      open <ссылка>              links
limit <ссылка> <лимит>      edit <ссылка> <адрес>      delete <ссылка>
user [uuid]                 logout                     exit
```

## Настройки

`src/main/resources/application.properties`:

```properties
storage.directory=data
link.domain=mifi.test
link.code-length=6
link.ttl=24h
link.default-limit=10
link.max-limit=1000
link.cleanup-interval=1m
```

## Что сделано по заданию

1. Сокращение: случайный код из 6 символов, один и тот же адрес у разных пользователей даёт разные ссылки.
2. Пользователь: UUID создаётся при первом `create` и хранится в `data/user.txt`, `user <uuid>` переключает на другого.
3. Права: менять и удалять ссылку может только владелец.
4. Лимит переходов: после последнего перехода ссылка блокируется, владелец может поднять лимит через `limit`.
5. Время жизни: задаётся в настройках, протухшие ссылки удаляет фоновый поток.
6. Уведомления: владелец сразу узнаёт, что лимит исчерпан или срок истёк, а если был не в сети, то при следующем запуске.
7. Переход: ссылка открывается в браузере через `Desktop.browse`.
8. Конфиг: все параметры в `application.properties`.
9. Валидация: адрес, лимит, UUID, число аргументов, неизвестные команды.
10. Данные лежат в `data/` и переживают перезапуск.

## Как создавался

1. Разбил ТЗ на пункты выше и начал с модели: `ShortLink` сам следит за лимитом, сроком и владельцем, поэтому правила не размазаны по коду.
2. Код ссылки случайный (base62, 6 символов, около 57 млрд вариантов) с проверкой, что он свободен. Хеш от адреса не подошёл: один адрес у разных пользователей должен давать разные ссылки.
3. Сценарии собрал в `LinkService`, а хранилища, генератор кодов и браузер вынес за интерфейсы, чтобы в тестах подменять их без файлов и браузера.
4. Данные хранятся в CSV: для учебного проекта база лишняя.
5. Протухшие ссылки удаляет фоновый поток, плюс срок проверяется при каждом обращении, чтобы ссылка не открылась между проходами очистки.
6. Консоль взял из прошлого проекта (личные финансы) и добавил то, чего не хватало: короткую ссылку можно просто вставить.
7. В конце тесты по этапу 3 из ТЗ и CI на GitHub Actions.

## Архитектура

```text
domain          ShortLink, Url, Notification
application     LinkService, Session + интерфейсы (port)
infrastructure  CSV, генератор кодов, браузер
presentation    консоль и команды
app             Main, конфиг, сборка зависимостей
```

Зависимости идут внутрь, к `domain`, это проверяет `ArchitectureTest` (ArchUnit). Хранилища, генератор кодов и браузер спрятаны за интерфейсами в `application.port`, время берётся из `Clock`, поэтому TTL проверяется в тестах без ожидания.

## Тестирование

```bash
mvn verify
```

JUnit 5, тестов больше 15: модель, сервис, консоль и сквозные сценарии (лимит, TTL, чужие ссылки, уведомления). JaCoCo требует покрытие строк от 75% (сейчас около 84%), Spotless проверяет форматирование, то же гоняется в GitHub Actions.
