# Личные финансы

Консольное приложение для учёта доходов и расходов с бюджетами по категориям. Java 17, Maven.

```bash
mvn package
java -jar target/finance-1.0.0.jar
```

Другой каталог для данных можно передать аргументом: `java -jar target/finance-1.0.0.jar my-data`.

## Как пользоваться

1. Запускаем приложение и регистрируемся, вход происходит сразу:

   ```text
   finance> register alice 1234
   Пользователь alice зарегистрирован
   Баланс: 0.00
   ```

   В следующий раз входим через `login alice 1234`, кошелёк загрузится из файла.

2. Создаём категории и бюджеты: `add-category Еда`, `budget Еда 4000`. Названия с пробелами пишем в кавычках.
3. Добавляем операции: `income Зарплата 60000`, `expense Еда 300`. Если бюджет почти кончился или превышен, приложение сразу предупредит.
4. Смотрим сводку: `report` по всем категориям, `report Еда Такси` по выбранным, `period 2026-11-01 2026-11-30` за период, `save-report отчёт.txt` в файл.
5. Переводим другому пользователю: `transfer bob 500`.
6. Выходим через `logout` или `exit`, кошелёк сохранится в `data/wallets/`.

## Команды

Полный список выводит `help`. Дата пишется как `ГГГГ-ММ-ДД`, по умолчанию сегодня.

```text
register <логин> <пароль>          login <логин> <пароль>       logout
income <категория> <сумма> [дата] [комментарий]
expense <категория> <сумма> [дата] [комментарий]
transfer <логин> <сумма>
add-category, rename-category, remove-category, categories
budget <категория> <сумма>         remove-budget <категория>
report [категория...]              period <с> <по> [категория...]
history [категория...]             save-report <файл> [категория...]
export <файл.csv>                  import <файл.csv>            exit
```

## Настройки

Настраивать почти нечего: единственный параметр это каталог данных (по умолчанию `data`).

```text
data/users.csv              логины и хеши паролей
data/wallets/<логин>.csv    категории, бюджеты и операции
```

## Что сделано по заданию

1. Хранение в памяти: пока приложение работает, кошелёк живёт в памяти.
2. Авторизация: `register` / `login`, пользователей сколько угодно, пароли хранятся хешем (PBKDF2).
3. Доходы и расходы: `income` / `expense`, категории создаются через `add-category`, бюджет через `budget`.
4. Кошелёк привязан к пользователю и хранит категории, бюджеты и все операции.
5. Вывод: `report` показывает доходы и расходы по категориям, итоги и остаток по бюджетам. `save-report` пишет то же в файл.
6. Подсчёты: можно передать несколько категорий (`report Еда Такси`). Если категории нет, будет ошибка с подсказкой.
7. Валидация: проверяются суммы, даты, логины, число аргументов и неизвестные команды.
8. Оповещения: превышение бюджета, расходы больше доходов, плюс 80% бюджета и нулевой баланс.
9. Сохранение: при `logout` / `exit` (и даже при Ctrl+C) кошелёк пишется в `data/wallets/<логин>.csv`, при входе читается обратно.
10. Команды читаются в цикле до `exit`.

Дополнительно:

- Переводы `transfer bob 500`: у отправителя расход, у получателя доход, категория `Переводы`.
- Отчёт за период `period 2026-11-01 2026-11-30`.
- Редактирование категорий и бюджетов: `rename-category`, `remove-category`, повторный `budget`, `remove-budget`.
- Экспорт и импорт кошелька в CSV.
- `help` с таблицей команд, цветной вывод и таблицы.

## Как создавался

1. Разбил ТЗ на пункты выше и начал с модели: `Wallet` хранит категории и операции и сам следит за правилами, например не даёт удалить категорию, в которой есть операции.
2. Деньги лежат в `Money` на `BigDecimal`: на `double` копейки теряются при сложении.
3. Каждое оповещение это отдельное правило за интерфейсом `AlertRule` (`BudgetRule`, `BalanceRule`), новое добавляется без правки остального кода.
4. Регистрацию, вход и переводы собрал в `AuthService` и `WalletService`, хранилища вынес за интерфейсы, чтобы в тестах подменять их.
5. Данные хранятся в CSV: у каждого пользователя свой файл, тот же формат используется для `export` / `import`.
6. Каждая команда консоли это отдельный класс, число аргументов проверяется по описанию параметров. Сама консоль от финансов не зависит.
7. В конце тесты, включая пример из задания, и CI на GitHub Actions.

## Архитектура

```text
domain          Wallet, Category, Operation, Money, Report, правила оповещений
application     AuthService, WalletService, Session + интерфейсы хранилищ (port)
infrastructure  файловые репозитории, CSV, хеширование пароля
presentation    консоль и команды
app             Main и сборка зависимостей
```

Зависимости идут внутрь, к `domain`, это проверяет `ArchitectureTest` (ArchUnit). Хранилища и хеширование пароля спрятаны за интерфейсами в `application.port`, `presentation.console` от финансов не зависит, его можно взять в следующий проект.

## Тестирование

```bash
mvn verify
```

JUnit 5, тестов больше 15: модель, сервисы, CSV, консоль и сквозные сценарии (пример из задания, сохранение и загрузка при перезапуске). JaCoCo требует покрытие от 50%, Spotless проверяет форматирование, то же гоняется в GitHub Actions.
